# 三段の送り装置

## 操作と推理

左右の案内軸は、ハンドルや見本の閲覧履歴がなくても四つの位置へ動く。ハンドルは送り駆動にだけ必要。見本の閲覧・操作・成功フラグは実機の操作条件にも正解条件にも使わない。

一回の送りで左右の設定を記録し、三回送った後にケースが到達するかを判定する。実機の途中の回転・段送り表示は入力回数だけを示し、正誤を示さない。失敗しても途中で入力を拒否しない。下中央の復帰つまみで最初に戻す。道具の喪失や時間罰はない。収納を開けると送りハンドルを手元へ戻す。

見本はガラス越しに三枚の隔壁・切り欠き・可動ケースを表示する。左右の突起の高さを合わせると先へ進み、違えばケースが止まったまま送り軸が空回りする。最初の不一致以降の送りでは進まないため、復帰が必要。両端の三日月／三つの鋲を押すと逆側から試せる。収納や報酬を持つ独立の謎ではない。

## 一つの形状定義

`src/transport.ts` の PARTITIONS が唯一の通過条件。高さは下から0〜3。三日月側は (0,3), (2,1), (3,2)。反対端では隔壁の順序を逆にし、各隔壁の左右を交換するため (2,3), (1,2), (3,0)。高さそのものは反転しない。

この同じ配列から見本の穴と両実機の正解列を作る。穴と正解を別の手書き定数で管理しない。各実機の設定列は4^6=4096通りで、成功列は一つ。これは組合せ検査であり、初見難易度の実測ではない。

## 保存

values.feed / backfeed は [現在の左, 現在の右, 1段目左, 1段目右, ...]。2,4,6,8要素だけを受け入れる。既存セーブの2要素は現在位置として読める。旧版の solved/opened/collected は維持し、解き直しを要求しない。表示中の見本の試行は実機の保存値を書き換えない。

## 表現と検証

三台とも同じ写真素材・操作部品で描画。反対側の実機では目印も左右が入れ替わる。全景と拡大は同じ装置を同じ座標から描く。手掛かりの図と写真の記録も旧レバー画像を使用しない。

見本の内部部品は通過条件から描く可動の金属表現で、写実生成した木・真鍮・ガラスの筐体と組み合わせる。通常画面へ操作手順、正解数字、正解段数を追加しない。三段の具体解説は任意ヒントの最終段階に限定。
